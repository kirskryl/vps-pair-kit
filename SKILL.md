# VPS Pair Kit

Этот репозиторий — источник инструкции. Владелец предоставляет доступ и проходит вход в свои учётные записи; агент изучает состояние, выполняет настройку, проверяет результат и исправляет сбои. Есть два входа: [новая пара HOME → EGRESS](references/pipeline.md) и [только Hermes на готовом сервере](references/hermes-only.md). Для согласованного Hermes читай также [его настройку](references/hermes.md). `scripts/kit.py` готовит только локальные файлы SS2022 и **не устанавливает** программы на VPS. [Руководство SS2022](VPS_PAIR_AGENT_GUIDE.md) относится к отдельному транспортному профилю.

## Порядок работы

1. Учитывай объём текущего запроса. Если пользователь попросил только план, изменение файлов или локальную проверку, не подключайся к VPS. Если он просит новую пару, установи роли ровно двух целевых VPS по записи провайдера и IP. Если просит Hermes на готовом сервере, следуй режиму «только Hermes» и не запускай этапы создания пары. Не угадывай роль по чужому SSH-профилю или существующей службе.
2. Для **новой пары** покажи абсолютный путь к `.env` в этом checkout и запусти `python3 scripts/kit.py status` до вопросов о данных. Спрашивай только то, чего нет. Если доступ пока только под root, используй `check-bootstrap`, создай и проверь разных администраторов, обнови тот же `.env`, затем выполни обычный `check`. `render` нужен только для выбранного профиля SS2022. В режиме **только Hermes** этот `.env` не требуется: используй подтверждённый доступ к существующему серверу и не переноси на него данные другой пары.
3. Для новой пары до выбора транспорта уточни объём: только связка VPS или также Hermes на HOME. Если текущий или предыдущий запрос уже явно включает Hermes, считай этап согласованным. При отказе или отсутствии ответа не устанавливай Hermes; заверши и проверь только связку серверов. Если согласие дано, ставь Hermes после проверки связи HOME → EGRESS. Запрос «установи только Hermes» уже согласует этот этап.
4. Оставь владельцу лишь действия, которые агент не может выполнить сам: вход в панель провайдера или ChatGPT и создание/авторизацию Telegram-бота. Общайся на языке владельца, давай одно понятное действие за раз и не перекладывай на него команды терминала. Токены и коды вводятся через защищённый локальный интерфейс или штатный вход Hermes, а не в чат и не в аргументы команд.

## Условия завершения

- Перед изменениями изучи состояние без записи и сохрани возможность отката. Отпечаток SSH-ключа сервера сверяй по независимому доверенному источнику, например консоли провайдера; одного `ssh-keyscan` недостаточно. Проблему SSH-доступа не решай переустановкой ОС.
- Меняй службы только явно выбранных серверов. При новой паре старые VPS не трогай; при установке Hermes на существующем сервере не меняй его сеть, SSH, firewall и чужие приложения без необходимости и отдельного согласования. Выполняй обратимые шаги и при повторном запуске опирайся на измеренное состояние. Код выхода 0 сам по себе не доказывает исправность службы.
- Для **новой пары с Hermes** проверенный маршрут — постоянный SSH SOCKS-туннель HOME → EGRESS с отдельным ключом. Для **готового сервера** сначала используй его уже настроенный выход и проверь реальный маршрут; не создавай новый туннель автоматически. Не запускай два конкурирующих маршрута Hermes и не допускай скрытого прямого выхода с HOME, если владелец требует выход через EGRESS.
- До сообщения «готово» выполни [приёмку](references/verification.md) для выбранного режима. Для новой пары проверь маршрут, отказ, восстановление и автозапуск. Для Hermes проверь модель ChatGPT, ответ и картинку в Telegram, русский голосовой ввод. Если проверка не прошла, исправь причину или верни предыдущее безопасное состояние и назови препятствие.
- Не обещай точную модель GPT Image 2 только на основании OAuth ChatGPT. Генерация через Codex в Hermes работает по возможности; если нужна гарантированная модель, предложи отдельный API-провайдер.

При локальном запросе меняй только файлы и запускай локальные проверки. Не обращайся к SSH, панели провайдера, Telegram и платным API лишь ради проверки инструкции.
