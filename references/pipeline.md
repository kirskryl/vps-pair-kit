# Порядок установки HOME → EGRESS; Hermes по согласованию

Эту процедуру выполняет агент **при настройке новой пары VPS**; для уже подготовленного сервера с запросом только на Hermes начинай с [отдельного входа](hermes-only.md). `kit.py` не является удалённым установщиком. Перед каждым действием агент проверяет фактическое состояние, пропускает уже выполненный шаг и фиксирует несекретные доказательства в закрытой локальной заметке. Для разработки не нужны чистые VPS: первичную установку и сбои можно воспроизводить в локальных VM и моках. Действующую пару проверяют только в пределах отдельного разрешения пользователя.

## 0. Цели и локальные данные

Определи **два новых** целевых VPS по ролям и записям провайдера. Запиши их ID в панели и IP в закрытую заметку, чтобы каждую удалённую команду сверять с нужным узлом. До выбора транспорта уточни объём одним вопросом: нужна только связка VPS или после неё нужен Hermes? Если запрос уже явно включает Hermes, повторно не спрашивай. Отсутствие ответа не означает согласия на Hermes. Узнай абсолютный путь checkout командой `pwd -P` и покажи его владельцу. Запускай `python3 scripts/kit.py init` только при отсутствии `.env`, затем `python3 scripts/kit.py status`. Не создавай второй `.env` в другом checkout и не перезаписывай уже сохранённый файл. Открывай редактор лишь для недостающих полей. Не печатай `.env` и секреты из генератора, не выполняй `source`, не передавай секреты аргументами команд и не добавляй их в Git.

`check-bootstrap` допускает временный вход root, в том числе с одним ключом для обоих новых VPS. `check` и `render` отвергают root и требуют разных путей к конечным ключам администраторов. Root в поле администратора означает переходный этап: администраторов создаёт агент, а не владелец. Если нет пути к ключу или SSH-доступа, один раз объясни, какого именно ввода не хватает. Проверяй права файлов, не читая содержимое приватных ключей.

## 1. Подлинность узлов и предварительная проверка

В панели провайдера сверь оба IP и наличие консоли восстановления. Получи отпечатки SSH host keys через независимый доверенный путь, сравни локально и закрепи отдельные записи `known_hosts` для HOME и EGRESS с обязательной проверкой. Если независимая сверка невозможна, останови действия с root-доступом и назови недостающее доказательство. Не переустанавливай ОС и не требуй пароль VNC-консоли, когда работает SSH по ключу.

Проверь версию ОС, архитектуру, systemd, ресурсы, слушающие порты, локальный и облачный firewall, SSH, версии пакетов и существующие службы. Старый baseline называл Debian 12/Ubuntu 24.04; для более новой системы, например Ubuntu 26.04 из этого опыта, нужна проверка совместимости, а не отказ по умолчанию или переустановка. Сохрани закрытые root-снимки затрагиваемых файлов и порядок отката. Не меняй firewall, пока не выяснены источник и порт административного SSH и способ восстановления доступа. Свободный порт подтверждается **пустым выводом списка слушателей**, а не кодом выхода команды. На каждом узле используй блокировку развёртывания.

## 2. Создание администраторов при доступе только под root

Если на новых VPS пока есть только root-доступ по ключу, создай или найди разные локальные пары ключей для конечных администраторов, установи каждый публичный ключ на свой узел и предоставь минимально необходимый `sudo` для настройки. До ограничения root/парольного SSH проверь свежий вход по ключу и `sudo -n` в отдельной сессии. На всех шагах используй уже закреплённый host key. Не заставляй владельца придумывать имена пользователей, вставлять приватные ключи или вводить root-пароль в VNC. Обнови имена и пути в исходном `.env`, выполни `check`; `render` выполняй, только если выбран SS2022. Если новый вход не работает, сохрани прежний root-доступ и исправь создание пользователей.

## 3. Сетевой шлюз

Если нужна только базовая связка серверов, используй [профиль SS2022](../VPS_PAIR_AGENT_GUIDE.md): два конфига, точная версия sing-box, `AF_NETLINK` в unit и проверки реального приложения, устойчивости и отказа. Если согласован Hermes, используй проверенный для него SSH-туннель ниже; не устанавливай SS2022 вдобавок без отдельной задачи. На этой паре первичная проверка SS2022 прошла, но позже трафик Hermes оказался нестабилен; одного `curl` недостаточно для признания профиля рабочим.

Если владелец выбрал Hermes, проверенный для него маршрут — SSH SOCKS-туннель. Создай на EGRESS непривилегированного пользователя `pairtunnel` с **новым** ключом, без `sudo` и административного входа, с разрешённым только необходимым SSH forwarding. Приватный ключ храни у `hermesagent` на HOME с правами 0600; там же закрепи host key EGRESS. Под надзором systemd запускай `ssh -N -D 127.0.0.1:<SOCKS_PORT>` с `ExitOnForwardFailure` и keepalive; слушатель — только на loopback. Настрой перезапуск службы и зависимость Telegram gateway от туннеля. Не используй для приложения root-ключи или ключи администраторов. Убедись, что HTTPS-запрос через SOCKS выходит с публичного IP EGRESS и завершается ошибкой при остановленном туннеле. Статуса `active` и открытого локального порта недостаточно.

У Hermes должен быть один выбранный маршрут: если владелец явно просит SS2022 вместо SSH-туннеля, проверь его на реальном трафике Hermes и не запускай одновременно второй маршрут. Не меняй общий firewall провайдера или пакетные службы, способные обслуживать старые приложения.

## 4. Решение о Hermes

После успешной проверки связи HOME → EGRESS выполни решение владельца об объёме, принятое на этапе 0. **Не устанавливай Hermes без ответа «да» или уже имеющегося явного запроса на Hermes.** Если он не нужен или ответ пока не получен, заверши только сетевую часть и её приёмку. Если нужен — переходи к [настройке Hermes](hermes.md): устанавливай его под отдельным пользователем `hermesagent` на HOME; EGRESS остаётся транспортным узлом. Конфигурация, авторизация, токен Telegram и ключ туннеля доступны только владельцу службы. Для бота не нужны публичные dashboard или API. Запиши точную версию Hermes и пути запуска, не полагайся на плавающее `latest`.

## 5. Приёмка и восстановление

Выполни [приёмку](verification.md) в согласованном объёме, затем покажи владельцу только необходимые действия и короткое состояние этапов. Сбой сохраняет последний безопасный маршрут и доступ. Не включай прямой выход HOME ради прохождения теста. Если Hermes установлен, перезапускай gateway из отдельной административной сессии: команда внутри самого gateway может быть уничтожена этим перезапуском. Если доступно, используй штатный `hermes gateway restart` с ожиданием нового процесса; затем проверь службу и соединение с Telegram. При исправлении systemd обращайся к найденному unit извне gateway.

При повторном запуске сначала выясни, какие пользователи, службы, порты, поколения зависимостей и настройки провайдера уже существуют. Совпадающие ресурсы сохраняй; расхождения покажи до замены. При откате восстанови лишь файлы, службы и правила этой пары, затем повтори проверки маршрута и согласованного приложения.
